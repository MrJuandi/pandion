# Design decisions and open questions

## Agreed direction

| ID | Decision | Rationale |
|---|---|---|
| D-01 | Build a new project separately from the earlier FireLab-RL prototype. | Preserve lessons while avoiding unreviewed legacy code, results, and assets. |
| D-02 | Start with one aircraft, then two, then consider more resource types. | Each increment permits a clear experimental question. |
| D-03 | Target a decision system for multiple heterogeneous resources. | The first aircraft is a research stage, not the final architecture limit. |
| D-04 | Use obtainable spatial products and explicit complementary features as controller inputs. | Align information with possible real deployment. |
| D-05 | Separate latent simulator state from controller observations. | Prevent privileged information and evaluate the value of sensing. |
| D-06 | Begin with CNN + non-spatial encoder and actor–critic; test LSTM later. | Preserve a measurable feed-forward baseline. |
| D-07 | Keep execution dynamics separate from mission selection. | Allow one decision API to scale to additional resources. |
| D-08 | Use a headless scientific core; decide interface packaging after replay needs are known. | Avoid coupling experiments to a UI. |
| D-09 | Name the new project Nightjar. | Use a distinctive, memorable name that can cover the planned progression from one aircraft to multiple resources. |
| D-10 | Use the Rothermel surface-fire equation as the first candidate spread calculation and a CL-415 as the first aircraft reference. | Both have primary technical sources; their use and limitations are specified in [PHYSICAL_MODEL_V0.md](PHYSICAL_MODEL_V0.md). This does not settle fuel models, numerical propagation, ground speed, or suppression effectiveness. |
| D-11 | Start implementation with a synthetic, deterministic aircraft kinematics and water-accounting episode. | It tests time, mission state, and volume conservation without implying that the unsourced ground-speed and refill proxies are CL-415 performance data. |
| D-12 | Use a separate synthetic grid-arrival fire episode to test spatial propagation before integrating the aircraft. | Its explicit base rates and exponential directional factors verify interface behavior but are not Rothermel or a physically calibrated fire model. |
| D-13 | Implement the published one-size dead-fuel Rothermel/Albini equations first with Anderson FM1, then test grid sensitivity. | FM1 has a single dead fuel size and published parameters, allowing a narrow equation check before heterogeneous fuels; the grid coupling and transfer to real vegetation remain unvalidated. |
| D-14 | Audit Copernicus EMSR578 AOI01 as a candidate independent observation series without using it to calibrate or claim validation. | It supplies versioned, timed burned-area polygons, but its vegetation, interventions, and weather history are not represented by current FM1 simulations. |
| D-15 | Introduce explicit observation capture, delivery, coverage, and age before a controller interface. | The synthetic schedule exposes information leaks early while making no claim about real sensor accuracy. |
| D-16 | Preserve an unfitted Anderson FM1 comparison to CSIRO Annaburroo grass-plot rates as an external diagnostic. | It tests model transfer without selecting parameters on evaluation data. The measured 0.5264 m/s mean absolute error and differences in fuel/ignition context preclude a validation claim. |
| D-17 | Integrate the existing fire, aircraft, and observation components first with a permanent, centre-based 35 m water barrier in a synthetic example. | This explicit and reversible hypothesis checks event ordering, information flow, action execution, and comparative metrics. It is not a sourced deposition or suppression law. |
| D-18 | Add a separate Pyretechnics-based standard-fuel surface-fire path while retaining the FM1 prototype. | It supports published fuel-model codes and live/dead moisture without treating Annaburroo plots as a universal FM1 calibration target. The grid-arrival coupling and real vegetation mapping remain unvalidated. |
| D-19 | Use the existing integrated FM1 synthetic episode as a fixed provisional decision-research environment. Permit explicitly exploratory controller experiments before geographic physical validation. | The episode already exercises delayed observations, action execution, and matched baselines. More spread-model development would delay testing the decision interface. Results from this environment describe only its declared assumptions; physical validation remains required for geographic or operational claims. |
| D-20 | Freeze a small, versioned family of synthetic variants before testing learned controllers. Keep development and reserved scenarios explicit, and vary ignition, wind, aircraft start, and the provisional water radius. | The single original map can reward a policy that memorizes its geometry or exploits one water-effect assumption. A fixed family can expose this sensitivity while preserving the same observation and action contract. The reserved cases are a diagnostic challenge set, not independent geographic incidents or a physically validated test. |
| D-21 | Add a separate synthetic decision challenge with a longer horizon, masked fuel cells, and delayed reports while retaining FM1 spread, aircraft execution, and the 35 m water rule. Generate reserved cases with independent seeds and do not run their outcomes during development. | The first eight-variant diagnostic leaves the heuristic at the same area for each water radius. Development cases can expose action-choice failures; unopened reserved outcomes provide a cleaner future check within the same provisional simulator. |
| D-22 | Retire the exploratory linear scorer and its training-only scenario generator after the first reserved comparison. | Its four-case result did not establish improvement over observation-matched heuristic or seeded random choice. Preserve the outcome record and treat those cases as opened; focus next on discriminating scenarios and stronger baselines. |
| D-23 | Introduce the multi-foci, asymmetric-transit discrimination family (`nightjar-discrimination-family-0.1`) with strictly disjoint development, validation, and unopened reserved splits. | The eight development cases show at least 4.0 ha unmitigated spread, reducing observed floor effects and creating spatial dispatch trade-offs. Protected ignition neighborhoods do not prove this threshold for the unopened splits. |
| D-24 | Add an informed containment reference (`containment_heuristic`) and predeclare quantitative improvement criteria before evaluating future candidate models. | The greedy heuristic ignores downstream fuel exposure, multi-burning neighbor bottlenecks, and transit latency. Predeclaring a minimum relevant effect (>= 0.50 ha vs heuristic, non-inferiority vs containment) and paired dominance prevents post-hoc selection bias. |
| D-25 | Discretize the action space as $2 + (H \times W)$ with boolean invalid-action masking and a hybrid CNN+MLP Actor-Critic network. | Mapping HOLD (0), REFILL (1), and DROP at $(r, c)$ ($2 + r \cdot W + c$) preserves the 2D grid structure while enforcing strict operational validity via logit masking, ensuring zero rejected orders without reading latent simulator state. |
| D-26 | Expose public elevation in integrated observations and append normalized elevation and slope raster channels to the tensorizer. | Static topography is scenario input rather than latent fire state; deriving channels from the delivered observation keeps the neural encoder aligned with the controller information budget while preserving existing action mapping and masking. |
| D-27 | Execute strictly one-time blind test protocol on `discrimination-reserved` with selected 16x8 PPO checkpoint; record outcomes and retire split as opened. | Preserves scientific integrity by refusing to re-train on the test set. The selected policy beat random dispatch (`6.719 ha` vs `7.013 ha`, 6 wins) with zero rejected orders, but failed to beat greedy or containment heuristics (`6.531 ha` and `6.281 ha`, 4 losses vs greedy). Reserved cases are now opened; future policy claims require fresh held-out scenarios. |
| D-28 | Introduce Recurrent PPO (LSTM) and Procedural Domain Randomization for Stage 1 policy training, while strictly rejecting imitation learning. | Resolves two primary failure modes from D-27: observation delay amnesia (60–120s satellite delays causing tactical abandonment without recurrent memory) and geometric overfitting (from training only on 8 development scenarios). Preserves pure RL without behavioral cloning or heuristic imitation. Maintains 100% backward compatibility with feedforward models (recurrent=False default). |
| D-29 | Introduce Tactical Action Abstraction (Macro-Actions: Head, Flanks, Rear, Closest, Refill, Hold) for Stage 1 one-aircraft decision research. | Reducing the discrete action space from 123 spatial coordinate logits to 8 structured tactical macro-actions eliminates spatial pixel-hunting, cross-map transit oscillation between disconnected foci, and local greediness. Connected components and wind-projection geometry operate strictly on delivered observations with zero latent state leakage. Maintains pure reinforcement learning without imitation. |
| D-30 | Integrate physical forward lookahead via Spread Risk Heatmap (Channel 10) and Containment Macro-Action (`ATTACK_CONTAINMENT_NEAREST`), achieving state-of-the-art pure RL suppression surpassing both greedy and containment baselines. | Equipping the spatial tensorizer with forward physical risk projection (channel 9) and expanding the tactical action palette to 9 macro-actions allows pure RL (no imitation or pretraining) to dynamically balance aggressive head attack against downstream containment and transit cycles. Evaluated across all 32 validation scenarios (`nightjar-discrimination-family-0.1`), PPO achieved 7.4219 ha mean burned area, beating both containment_heuristic (7.6484 ha, -0.2266 ha reduction, 17 wins, 8 losses, 7 ties) and greedy heuristic (7.7266 ha, -0.3047 ha reduction, 17 wins, 3 losses, 12 ties) with 100% zero rejected orders. Preserves pure RL and zero latent leakage. |
| D-31 | Execute strictly one-time blind evaluation on fresh 32-scenario held-out benchmark (`discrimination-reserved-v2`, schema `nightjar-reserved-evaluation-0.2`) with tactical recurrent PPO checkpoint, accompanied by bootstrap 95% confidence intervals and regression diagnostic on opened v1 split. | Resolves O-11 and satisfies the Stage 1 Gate requirement in the provisional synthetic simulator. On the 32 virgin held-out scenarios, PPO achieved 7.7734 ha mean affected area vs 8.0234 ha for greedy heuristic (59.4% wins, 18.8% losses, 95% CI [-0.0156, 0.5234] ha) and 8.0312 ha for containment heuristic (50.0% wins, 18.8% losses, 95% CI [0.0000, 0.5469] ha), with 100% zero rejected orders. Direct diagnostic on opened v1 split confirmed resolution of the reserved-06 failure mode (PPO 5.75 ha vs old PPO 8.25 ha, saving 2.50 ha / 10 cells). Closes Stage 1 evaluation in the synthetic simulator. |
| D-32 | Establish the first real geographic pilot data pipeline and fuel crosswalk on Copernicus EMSR578 AOI01 (Artesa de Segre wildfire, June 2022) with ETRS89 / UTM Zone 31N projection (`EPSG:25831`) and Scott & Burgan 40 model mapping. | Advances Stage 0 physical validation by moving beyond toy synthetic grids. Implements exact sub-millimeter transverse Mercator geodesy, maps all 13 CORINE Land Cover classes present in AOI01 to Scott & Burgan 40 fuel models with documented botanical rationales and confidence ratings, extracts water sources (Pantà de Rialb, Riu Segre) for CL-415 scooping, rasterizes initial perimeter at 100 m resolution (1,500.0 ha vs 1,501.73 ha reported, -0.12% error), and implements spatial validation metrics (IoU, Dice, commission/omission). Does not claim in-situ fuel validation; preserves uncertainty and sets prerequisites for atmospheric time-series reconstruction and spread evaluation. |
| D-33 | Implement an exploratory Rothermel/Pyretechnics surface-fire pilot and satellite spatial diagnostics on EMSR578 AOI01. | Historical flat-terrain runs used unsourced constant moisture and wind. A one-hour run produced 2,071 ha versus the day-later 2,108 ha raster; this is a time-mismatched area fit, not an observed active-burning duration or physical validation. The 88,860-second run overpredicted area (15,924 ha). The discrepancy does not identify suppression, nighttime recovery, or another mechanism as its cause. See the corrected interpretation in [VALIDATION_EMSR578.md](VALIDATION_EMSR578.md). |
| D-34 | Establish universal geodesy (UTM Zones 29N, 30N, 31N), multi-incident CEMS ingestion (`nightjar.cems_catalog`), and real-world geographic scenario family (`nightjar.geographic_family`) across strictly disjoint splits. | Solves O-01 by preventing single-incident overfitting. Generalizes Krüger transverse Mercator series to any UTM zone without external GIS dependencies, expands the botanical CORINE-to-Scott & Burgan crosswalk to 18 classes (adding olive groves NB, pastures GR2, heathland SH6, sparse grass GR1, inland marshes NB), registers four CEMS wildfire products with SHA-256 digests; the original three misidentified incident labels and Massarosa projection were corrected under D-43, and builds tactical decision scenarios partitioned strictly by geographic incident: EMSR578 for development, EMSR590 for validation, and EMSR592/EMSR600 for held-out reserved benchmarking. |
| D-35 | Real-World Geographic Integrated Decision Environment (`nightjar.geographic_integrated`) and Comparative Multi-Policy Benchmark (`nightjar.geographic_benchmark`). | Couples Copernicus CEMS geographic scenario suites (`nightjar-geographic-family-0.1`), Scott & Burgan 40 fuels, Rothermel / Pyretechnics fire spread, and georeferenced CL-415 operations (80 m/s cruise, 55 m/s drop, 180 s refill at natural waterbodies). Implements strict zero-leakage observation filtering and evaluates deterministic baseline policies (`no_intervention`, `random_valid`, `heuristic`, `containment_heuristic`). |
| D-36 | Geographic Reinforcement Learning Pipeline: `GeographicTrainingEnv` and Geographic PPO with Tactical Macro-Actions and Recurrent Memory (`nightjar.geographic_ppo`). | Adapts the headless step/reset reinforcement learning interface (`GeographicTrainingEnv`) to real-world CEMS wildfire scenarios, generalizing `ObservationTensorizer` to Scott & Burgan 40 fuels. Couples 9 tactical macro-actions and recurrent LSTM memory with clipped PPO and BPTT updates, supporting training on development (EMSR578) and candidate selection on validation (EMSR590) with zero latent state leakage and zero rejected orders. |
| D-37 | Geographic family generation defaults to requiring all four CEMS incident bases; synthetic fixtures require an explicit opt-in. | The CLI reads local `<activation>_del.zip` products without downloading, labels explicitly synthetic outputs, rejects mismatched mapping/activation IDs and conflicting source classification in both modes, allocates reserved scenarios across EMSR592/EMSR600, and refuses a non-empty destination to prevent stale membership. This is a source-classification and split-integrity contract only: flat topography and the family's physical-validation gate remain open. |
| D-38 | Bind geographic scenarios and PPO outputs to verified source and scenario content; never substitute fixtures during loading. | The builder checks actual CEMS ZIP bytes against the unchanged catalog digest and carries acquisition/product/CRS/unit/resolution plus canonical crop and scenario hashes forward. PPO accepts only manifest-matched real splits with unique file membership and consistent catalog product metadata by default; offline fixtures require explicit `--synthetic` and a generated synthetic dataset. Fuels are inferred, weather/surveys synthetic, and topography flat; this is metadata integrity, not physical training readiness. |
| D-39 | Make the existing geographic spatial convention explicit without changing action or aircraft physics. | CEMS cells are sampled at centers from a southwest-boundary origin; rows increase north and columns east. Current discrete actions are local cell-anchor proxies and replay UTM adds the crop origin; they are not measured physical drop centers. Cropped water remains an explicit static layer. Fuel code 0 cannot identify nodata/source coverage because it also represents water, nonburnable, and unmapped cells. Flat terrain needs no current DEM. Spatial alignment is a geographic landscape/data gate, narrower than full Stage 0 physical validation. |
| D-40 | Verify the geographic PPO interface on development only, with explicit training seeds and weights-file checks. | `--seed` defaults to 42 and is recorded in smoke/train/selection reports; smoke can save a raw model state dictionary and a missing resume file is rejected. Loading restores weights into a fresh optimizer, without restoring optimizer/RNG state or promising cross-platform identity. CPU PyTorch tests are exercised by a separate CI job. The [verification record](GEOGRAPHIC_PPO_VERIFICATION.md) establishes technical execution and serialization checks; the physical and policy-performance gates remain open. |
| D-41 | Begin environmental reconstruction with separately bound numeric terrain and station-coverage artifacts; compare cumulative and newly burned area only at explicit elapsed times. | IGN/CNIG 25 m terrain is sampled/reprojected to the 100 m EMSR578 pilot grid, with unknown acquisition epoch and unadvertised source footprint kept explicit. Baldomar XEMA observations are audited at their forward half-hour intervals and remain separate from engine forcing and controller observations. EMSR578 is development evidence; daily snapshots do not establish within-day arrival times or independent generalization. See [PILOT_ENVIRONMENT.md](PILOT_ENVIRONMENT.md). |
| D-42 | Separate replay, pair comparison, model inspection and records in a portable offline research workspace. | Four task views keep spatial playback legible while exposing actual PPO checkpoint architecture and synthetic physical inputs. The compact dark workstation follows FireLab’s map/telemetry/playback organization; scenario/controller selection is explicit and model provenance is expandable. Canvas measurement follows panel insertion to preserve cell proportions. Models and Records own vertical desktop scrolling and use document scrolling on narrow screens. Native in-app-browser QA supplements Chromium checks. A filled inline SVG bird mark remains legible at toolbar size without external assets. Python may record a supplied checkpoint on an explicit scenario; the browser consumes records only. Compatible final-metric deltas and arrival-area curves are descriptive, with no statistical ranking. Retrospective truth, final outcomes and delivered observations stay distinct. Missing geographic fields remain unavailable. Source/hash bindings document evidence and deferred scope. Superseded by D-48. |
| D-43 | Provide a Spanish offline workspace with scenario/policy selection, synchronized comparisons and numeric 3D terrain; keep display DEMs separate from existing flat-terrain experiments. | The 24 geographic variants span four incidents, while the current geographic checkpoint has only development technical verification. Reuse source-bound IGN/CNIG pilot terrain as a labeled visual overlay and historical full-landscape view; execute only development cases and show validation/reserved maps without outcomes. Preserve controller observation boundaries and record issuance/completion times in geographic replay 0.2. |
| D-44 | Validate incident identity against official product maps and WGS84 AOI envelopes in addition to ZIP digest. | EMSR590 AOI01 is Ladrillar/Las Hurdes (2022-07-14 10:48 UTC), EMSR592 AOI01 Landiras, France (2022-07-17 10:26 UTC), and EMSR600 AOI01 Massarosa, Italy (2022-07-21 10:23 UTC; EPSG:25832). | D-45 | Derive a versioned environmental family and use real heights plus time-dependent dry station forcing in geographic physics. | All four incidents receive aligned 100 m elevation samples (IGN terrain for Spain; Copernicus GLO-30 DSM proxy for France/Italy). Artesa receives Baldomar measured weather, uncalibrated station-to-midflame factor 1.0 and modeled Simard/lag dead moisture; live/initial moisture remains modeled. Integrate edge travel across forcing changes and expose completed intervals only to controllers. Reward and provisional water barriers are unchanged. New development-only weights are required; no physical or performance gate is closed. |
| D-46 | Organize the offline replay viewer as a 3D-first research workstation for both explanation and analysis. | Separate map/comparison, environmental conditions and provenance views; keep scenario/time context, distinguish final episode totals from the latest issued decision, and preserve observation-only boundaries. Use a perspective WebGL mesh without vertical exaggeration, smooth normals, lighting and DEM-derived contours, with a fitted camera, explicit scalar legends and keyboard navigation. Comparison is strictly one selected policy against one selected reference, with synchronized camera/time and pair-specific horizons. Embed pinned Three.js r128 with its MIT license; expose an explicit compatibility fallback when WebGL is unavailable. This is presentation behavior, not new physical or policy evidence. Design references consulted 2026-10-01: [QGIS 3.44 3D navigation](https://docs.qgis.org/3.44/en/docs/user_manual/map_views/3d_map_view.html) and [ParaView 6.0 scalar legends](https://docs.paraview.org/en/v6.0.0/ReferenceManual/colorMapping.html). The local FireLab-RL viewer informed workspace layout and the mesh/material/perspective rendering approach; no model assumptions, artificial terrain, flame effects, benchmark claims or unrecorded aircraft altitude were imported. Perspective scale is local to the camera focal plane; display surfaces interpolate the source grid without adding physical resolution. |
| D-47 | Rebuild the offline replay viewer as an interactive Three.js scene modelled on the local FireLab-RL viewer, keeping the D-46 views and data boundaries. | The project owner judged the D-46 renderer (WebGL copied into a 2D canvas with a fixed camera) visually deficient compared with FireLab. The new viewer uses a live WebGL scene with OrbitControls r128 (pinned with Three.js r128), shadows, a based terrain block and an extended reference floor, a time-dependent terrain texture, an amphibious-tanker symbol on the recorded track, camera presets (3D, orthographic 2D, chase, front), HUD, live metrics, A(t) curves and a wind-aligned elevation profile. Unchanged: every quantitative layer is drawn from the replay at the selected time (active front = reached cells with a burnable unreached 4-neighbour), observation mode hides simulator truth, comparisons are strictly two policies, and nothing is fed to a controller. It lives in `nightjar.viewer` and is used by `nightjar.workspace` (see D-48). Presentation only; no physical or policy evidence. |
| D-48 | Keep a single offline replay viewer: the D-47 3D viewer, under `nightjar.viewer`. | D-49 | Geographic episodes assume a fully observed area in real time: `observation_mode="realtime"` is the default and the delayed schedule remains available as `"scheduled"`. Cells report `unburned`/`burning`/`burned`; a cell burns for the front crossing time (cell size / head-fire rate) plus Anderson (1969) residence 384/σ min. | The project owner set zero information delay and full observation as the operating assumption (drone-type real-time coverage). Every decision now sees every cell at age 0, the forcing interval containing the decision time (wind, station weather, fuel moisture) and no future interval or arrival; this revises D-15 delivery semantics and the D-45 completed-interval rule for geographic controllers only. Observation is perfect: no detection, geolocation or segmentation error is modelled yet. Station interval means are treated as known during the interval, which is part of the real-time assumption, not a measurement claim. Anderson residence alone is seconds for these fuels, invisible at 60 s decisions on 50–100 m cells, so the crossing term dominates; flank fronts cross more slowly than the head rate, so burning durations are lower bounds. In the mapped initial perimeter only cells bordering unburned burnable fuel are burning at t=0; interior cells are already burned. D-28 recurrent memory is kept by owner decision to infer fire trends. Synthetic FM1 families keep their delayed schedules. This is the first step of the agreed policy-input redesign (per-cell CNN rasters incl. a Sentinel-2 RGB composite at 8×8 px/cell with fire/burned/water overlays, DEM elevation and gradient, prior fuel map, treated cells, aircraft distance map; global vector of wind, temperature, RH, uniform fuel moisture, aircraft state and time; optional Rothermel ROS channel for ablation). Existing geographic weights were trained on delayed views and must be retrained. |
| D-50 | Acquire one pre-fire Sentinel-2 L2A true-colour base image per geographic activation grid (`nightjar.imagery_acquire`) at 8 px per 100 m cell. | Base layer for the D-49 image input. Scenes are searched 75 to 14 days before the CEMS activation time (the ignition time is not in the API, so the margin is conservative), screened by their own SCL classes inside the crop with a 100 m cloud/shadow buffer, and composited best-available-pixel with per-channel mean/std matching of filler scenes. Acquired 2026-10-02 for the nine activation grids of `runs/geographic-environment-family-expanded-20261002`: eight are single clear scenes (2022-05-28 to 2022-08-03); EMSR578 needed three spring scenes (2022-04-30 primary, 91.9% of pixels). Registration check: correlation between burnable fuel cells and cell greenness is highest for the stored orientation where the fuel map has contrast (EMSR600 +0.50 vs +0.02 flipped and +0.21 mirrored; EMSR583 +0.23; EMSR602_AOI04 +0.24); grids with almost no nonburnable cells give no signal. TCI is a display product; pre-fire phenology and composite seams are accepted limits. Images, previews and manifests stay out of Git. |
| D-51 | Draw the per-step policy view as the pre-fire base image with burning, burned and treated cells blended over it from the real-time controller observation (`nightjar.imagery_composite`). | Models the D-49 real-time aerial view without a sensor simulator. Colours are a declared rendering convention: burning toward flame orange (α 0.85), burned toward char (α 0.80), treated toward a water/retardant blue (α 0.55); burning is drawn last. Overlays are whole-cell blocks at the 100 m grid, so the view carries no sub-cell fire geometry. Inputs come only from the controller observation (`fire_state`, `known_treated_cells`); delayed observations are rejected because they lack the burning/burned distinction. Smoke, flame occlusion, sensor noise and retardant colour variation are not modelled. |
| D-52 | Add D-49 image policy inputs and an image actor-critic alongside the legacy geographic path (`--input-mode image`). | `GeographicInputTensorizer` emits the D-51 view (3×H·8×W·8), per-cell channels (normalized elevation, dz/dx, dz/dy, seven Scott & Burgan/Anderson fuel families, treated cells, aircraft distance, optional Rothermel head-fire ROS) and a 15-value global vector (wind, station temperature/RH with validity flag, six fuel-moisture classes, water fraction, idle flag, refill time, elapsed time). Fire state reaches the policy only through the image, by owner decision. `ImageActorCritic` reduces the image to one feature vector per cell with a kernel=stride=8 convolution, FiLM-conditions three residual blocks on the vector, keeps the optional LSTM, and offers tactical (9 macro-actions) or spatial (HOLD, REFILL, one logit per cell) heads. A one-update smoke run on development EMSR578 with real imagery completed in both action modes with zero rejected orders. Legacy inputs stay the default, so existing commands and checkpoints keep their meaning; image training needs new weights and has no performance evidence yet. |
| D-53 | Add a no-image ablation (`--input-mode cells`) of the D-52 model for a fair architecture comparison. | Comparing the image model with the legacy `SpatialActorCritic` changes both network and inputs, and the legacy path receives fire state already resolved. The ablation keeps the same `ImageActorCritic` trunk, FiLM conditioning, LSTM, heads, per-cell channels and vector, removes the RGB encoder, and supplies fire state as three explicit per-cell channels (burning, burned, time since front arrival over the horizon). The only difference from `--input-mode image` is how fire state reaches the policy, so the comparison measures the cost or benefit of perceiving fire from the image. |
| D-54 | Speed up geographic training without changing results: persistent episode stepping, cheaper defensive copies, per-episode gradient accumulation, selectable torch device and partial checkpoints. | Profiling showed one image-model update took about 150 s on one CPU thread: the training environment replayed the whole action prefix at every step (quadratic), deep-copied full-grid observations three times per step, and BPTT over eight 320×320 episodes in one graph exhausted memory on Apple MPS (6 s, 62 s, 99 s on consecutive updates). The episode loop is now a generator (`geographic_episode`) that the batch driver and the environment share; 30 recorded cases (four policies × two observation modes, truncated runs and full environment trajectories on three development scenarios) are byte-identical before and after. Copies use pickle instead of deepcopy (8.0 → 1.4 ms per observation). PPO accumulates gradients one episode at a time with each episode's sums divided by the total step count, which equals the batched loss gradient (tested, max difference ~1e-8). `--device {cpu,mps,cuda,auto}` and `--checkpoint-every N` (weights to `<checkpoint>.partial`) are new. Measured on development EMSR578, 8 episodes per update: image model on MPS 13.8 s per update (from ~150 s), no-image ablation 9.8 s on MPS, legacy 9.2 s on CPU. GPU runs are not bit-reproducible across devices. |
| D-55 | Add standard PPO options to the geographic trainer: multiple epochs over whole-episode minibatches, GAE(λ), reward scaling by the running std of discounted returns, batch advantage normalization and approximate-KL early stopping. Defaults reproduce the original update. | The original update took one optimizer step per batch, so 60 updates were 60 gradient steps, and unscaled returns made the critic loss about 5,000 while gradients were clipped to norm 0.5, leaving little policy signal. `--ppo-epochs`, `--minibatches` (groups of whole episodes so LSTM sequences stay intact), `--gae-lambda`, `--reward-scaling` and `--target-kl` enable the standard remedies; scaling statistics include the batch being scaled. Tests: GAE with λ=1 equals Monte Carlo advantages and λ=0 equals one-step TD; the scaler matches the return std; more epochs move weights further; defaults keep the per-episode normalized single-step update. On development EMSR578 (cells ablation, MPS, 4 epochs × 4 minibatches, λ=0.95, scaling, target KL 0.02) the loss is about 0.4 from the first update instead of about 5,000, at about 13 s per update. No performance claim yet. |
| D-56 | Derive an initial-attack family (`nightjar.ignition_family`) that keeps each parent scenario's fuels, terrain, water, weather and observation schedule but replaces the CEMS delineation with a 5x5 or 7x7-cell ignition sampled among burnable cells inside the mapped burned area. | Starting from the delineation polygon left most of the window already burned (EMSR578: 1146 of 1600 cells), so only ~200 ha could still change in one hour, policies differed by ~30 ha, and all variants of one incident shared one map. With small ignitions, unmitigated growth ranges ~47–191 ha and heuristics differ by tens of hectares. 3x3 ignitions were rejected because both heuristics contained them without growth. Ignition centres are not reported origins; splits and incidents are inherited unchanged and reserved files stay unopened. |
| D-57 | Register five more Spanish CEMS delineation AOIs as development-only incidents: EMSR583 (Castejón de Tornos), EMSR625 AOI01 (Bejís) and AOI02 (Vall d'Ebo), EMSR602 AOI02 (San Esteban de Valdueza) and AOI04 (Cebreros). | Development previously held one incident, so a policy could memorise a single map. Validation (EMSR590) and reserved (EMSR592, EMSR600) are unchanged; the original 24 scenarios regenerate with identical hashes. Packages are verified by SHA-256 and terrain comes from IGN WCS as for the other Spanish incidents. Image acquisition times appear only on map PDFs that were not retrieved, so they are recorded as null with the activation-page delivery time. Unmapped CORINE classes (213, 241, 244) remain non-burnable under the existing crosswalk default. Sierra de la Culebra (EMSR580) and Losacio (EMSR602 AOI01) have no delineation product and were not added. |
