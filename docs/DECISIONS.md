# Design decisions and open questions

The 2026-10-06 [research-workspace contract](RESEARCH_WORKFLOWS.md) settles
generation clocks outside new scenario identities, explicit derivation seeds,
hash-bound model reports, shared inference, per-aircraft replay and CEMS
activation groups as future holdout independence units. Archived hashes and
historical experiment meanings remain intact. This named contract avoids
reusing decision numbers already assigned on concurrent branches.

## Agreed direction

| ID | Decision | Rationale |
|---|---|---|
| D-01 | Build a new project separately from the earlier FireLab-RL prototype. | Preserve lessons while avoiding unreviewed legacy code, results, and assets. |
| D-02 | Start with one aircraft, then two, then consider more resource types. | Each increment permits a clear experimental question. |
| D-03 | Target a decision system for multiple heterogeneous resources. | The first aircraft is a research stage, not the final architecture limit. |
| D-04 | Use obtainable spatial products and explicit complementary features as controller inputs. | Align information with possible real deployment. |
| D-05 | Separate latent simulator state from controller observations. | Prevent privileged information and evaluate the value of sensing. |
| D-06 | Begin with CNN + non-spatial encoder and actor–critic; test LSTM later. | Preserve a measurable feed-forward baseline. |
| D-07 | Keep execution dynamics separate from mission selection. | Allow one decision API to scale to additional resources. |
| D-08 | Use a headless scientific core; decide interface packaging after replay needs are known. | Avoid coupling experiments to a UI. |
| D-09 | Name the new project Nightjar. | Use a distinctive, memorable name that can cover the planned progression from one aircraft to multiple resources. |
| D-10 | Use the Rothermel surface-fire equation as the first candidate spread calculation and a CL-415 as the first aircraft reference. | Both have primary technical sources; their use and limitations are specified in [PHYSICAL_MODEL_V0.md](PHYSICAL_MODEL_V0.md). This does not settle fuel models, numerical propagation, ground speed, or suppression effectiveness. |
| D-11 | Start implementation with a synthetic, deterministic aircraft kinematics and water-accounting episode. | It tests time, mission state, and volume conservation without implying that the unsourced ground-speed and refill proxies are CL-415 performance data. |
| D-12 | Use a separate synthetic grid-arrival fire episode to test spatial propagation before integrating the aircraft. | Its explicit base rates and exponential directional factors verify interface behavior but are not Rothermel or a physically calibrated fire model. |
| D-13 | Implement the published one-size dead-fuel Rothermel/Albini equations first with Anderson FM1, then test grid sensitivity. | FM1 has a single dead fuel size and published parameters, allowing a narrow equation check before heterogeneous fuels; the grid coupling and transfer to real vegetation remain unvalidated. |
| D-14 | Audit Copernicus EMSR578 AOI01 as a candidate independent observation series without using it to calibrate or claim validation. | It supplies versioned, timed burned-area polygons, but its vegetation, interventions, and weather history are not represented by current FM1 simulations. |
| D-15 | Introduce explicit observation capture, delivery, coverage, and age before a controller interface. | The synthetic schedule exposes information leaks early while making no claim about real sensor accuracy. |
| D-16 | Preserve an unfitted Anderson FM1 comparison to CSIRO Annaburroo grass-plot rates as an external diagnostic. | It tests model transfer without selecting parameters on evaluation data. The measured 0.5264 m/s mean absolute error and differences in fuel/ignition context preclude a validation claim. |
| D-17 | Integrate the existing fire, aircraft, and observation components first with a permanent, centre-based 35 m water barrier in a synthetic example. | This explicit and reversible hypothesis checks event ordering, information flow, action execution, and comparative metrics. It is not a sourced deposition or suppression law. |
| D-18 | Add a separate Pyretechnics-based standard-fuel surface-fire path while retaining the FM1 prototype. | It supports published fuel-model codes and live/dead moisture without treating Annaburroo plots as a universal FM1 calibration target. The grid-arrival coupling and real vegetation mapping remain unvalidated. |
| D-19 | Use the existing integrated FM1 synthetic episode as a fixed provisional decision-research environment. Permit explicitly exploratory controller experiments before geographic physical validation. | The episode already exercises delayed observations, action execution, and matched baselines. More spread-model development would delay testing the decision interface. Results from this environment describe only its declared assumptions; physical validation remains required for geographic or operational claims. |
| D-20 | Freeze a small, versioned family of synthetic variants before testing learned controllers. Keep development and reserved scenarios explicit, and vary ignition, wind, aircraft start, and the provisional water radius. | The single original map can reward a policy that memorizes its geometry or exploits one water-effect assumption. A fixed family can expose this sensitivity while preserving the same observation and action contract. The reserved cases are a diagnostic challenge set, not independent geographic incidents or a physically validated test. |
| D-21 | Add a separate synthetic decision challenge with a longer horizon, masked fuel cells, and delayed reports while retaining FM1 spread, aircraft execution, and the 35 m water rule. Generate reserved cases with independent seeds and do not run their outcomes during development. | The first eight-variant diagnostic leaves the heuristic at the same area for each water radius. Development cases can expose action-choice failures; unopened reserved outcomes provide a cleaner future check within the same provisional simulator. |
| D-22 | Retire the exploratory linear scorer and its training-only scenario generator after the first reserved comparison. | Its four-case result did not establish improvement over observation-matched heuristic or seeded random choice. Preserve the outcome record and treat those cases as opened; focus next on discriminating scenarios and stronger baselines. |
| D-23 | Introduce the multi-foci, asymmetric-transit discrimination family (`nightjar-discrimination-family-0.1`) with strictly disjoint development, validation, and unopened reserved splits. | The eight development cases show at least 4.0 ha unmitigated spread, reducing observed floor effects and creating spatial dispatch trade-offs. Protected ignition neighborhoods do not prove this threshold for the unopened splits. |
| D-24 | Add an informed containment reference (`containment_heuristic`) and predeclare quantitative improvement criteria before evaluating future candidate models. | The greedy heuristic ignores downstream fuel exposure, multi-burning neighbor bottlenecks, and transit latency. Predeclaring a minimum relevant effect (>= 0.50 ha vs heuristic, non-inferiority vs containment) and paired dominance prevents post-hoc selection bias. |
| D-25 | Discretize the action space as $2 + (H \times W)$ with boolean invalid-action masking and a hybrid CNN+MLP Actor-Critic network. | Mapping HOLD (0), REFILL (1), and DROP at $(r, c)$ ($2 + r \cdot W + c$) preserves the 2D grid structure while enforcing strict operational validity via logit masking, ensuring zero rejected orders without reading latent simulator state. |
| D-26 | Expose public elevation in integrated observations and append normalized elevation and slope raster channels to the tensorizer. | Static topography is scenario input rather than latent fire state; deriving channels from the delivered observation keeps the neural encoder aligned with the controller information budget while preserving existing action mapping and masking. |
| D-27 | Execute strictly one-time blind test protocol on `discrimination-reserved` with selected 16x8 PPO checkpoint; record outcomes and retire split as opened. | Preserves scientific integrity by refusing to re-train on the test set. The selected policy beat random dispatch (`6.719 ha` vs `7.013 ha`, 6 wins) with zero rejected orders, but failed to beat greedy or containment heuristics (`6.531 ha` and `6.281 ha`, 4 losses vs greedy). Reserved cases are now opened; future policy claims require fresh held-out scenarios. |
| D-28 | Introduce Recurrent PPO (LSTM) and Procedural Domain Randomization for Stage 1 policy training, while strictly rejecting imitation learning. | Resolves two primary failure modes from D-27: observation delay amnesia (60–120s satellite delays causing tactical abandonment without recurrent memory) and geometric overfitting (from training only on 8 development scenarios). Preserves pure RL without behavioral cloning or heuristic imitation. Maintains 100% backward compatibility with feedforward models (recurrent=False default). |
| D-29 | Introduce Tactical Action Abstraction (Macro-Actions: Head, Flanks, Rear, Closest, Refill, Hold) for Stage 1 one-aircraft decision research. | Reducing the discrete action space from 123 spatial coordinate logits to 8 structured tactical macro-actions eliminates spatial pixel-hunting, cross-map transit oscillation between disconnected foci, and local greediness. Connected components and wind-projection geometry operate strictly on delivered observations with zero latent state leakage. Maintains pure reinforcement learning without imitation. |
| D-30 | Integrate physical forward lookahead via Spread Risk Heatmap (Channel 10) and Containment Macro-Action (`ATTACK_CONTAINMENT_NEAREST`), achieving state-of-the-art pure RL suppression surpassing both greedy and containment baselines. | Equipping the spatial tensorizer with forward physical risk projection (channel 9) and expanding the tactical action palette to 9 macro-actions allows pure RL (no imitation or pretraining) to dynamically balance aggressive head attack against downstream containment and transit cycles. Evaluated across all 32 validation scenarios (`nightjar-discrimination-family-0.1`), PPO achieved 7.4219 ha mean burned area, beating both containment_heuristic (7.6484 ha, -0.2266 ha reduction, 17 wins, 8 losses, 7 ties) and greedy heuristic (7.7266 ha, -0.3047 ha reduction, 17 wins, 3 losses, 12 ties) with 100% zero rejected orders. Preserves pure RL and zero latent leakage. |
| D-31 | Execute strictly one-time blind evaluation on fresh 32-scenario held-out benchmark (`discrimination-reserved-v2`, schema `nightjar-reserved-evaluation-0.2`) with tactical recurrent PPO checkpoint, accompanied by bootstrap 95% confidence intervals and regression diagnostic on opened v1 split. | Resolves O-11 and satisfies the Stage 1 Gate requirement in the provisional synthetic simulator. On the 32 virgin held-out scenarios, PPO achieved 7.7734 ha mean affected area vs 8.0234 ha for greedy heuristic (59.4% wins, 18.8% losses, 95% CI [-0.0156, 0.5234] ha) and 8.0312 ha for containment heuristic (50.0% wins, 18.8% losses, 95% CI [0.0000, 0.5469] ha), with 100% zero rejected orders. Direct diagnostic on opened v1 split confirmed resolution of the reserved-06 failure mode (PPO 5.75 ha vs old PPO 8.25 ha, saving 2.50 ha / 10 cells). Closes Stage 1 evaluation in the synthetic simulator. |

| D-49 | Geographic episodes assume a fully observed area in real time: `observation_mode="realtime"` is the default and the delayed schedule remains available as `"scheduled"`. | D-54 | Speed up geographic training without changing results: persistent episode stepping, cheaper defensive copies, per-episode gradient accumulation, selectable torch device and partial checkpoints. | Profiling showed one image-model update took about 150 s on one CPU thread: the training environment replayed the whole action prefix at every step (quadratic), deep-copied full-grid observations three times per step, and BPTT over eight 320×320 episodes in one graph exhausted memory on Apple MPS (6 s, 62 s, 99 s on consecutive updates). The episode loop is now a generator (`geographic_episode`) that the batch driver and the environment share; 30 recorded cases (four policies × two observation modes, truncated runs and full environment trajectories on three development scenarios) are byte-identical before and after. Copies use pickle instead of deepcopy (8.0 → 1.4 ms per observation). PPO accumulates gradients one episode at a time with each episode's sums divided by the total step count, which equals the batched loss gradient (tested, max difference ~1e-8). `--device {cpu,mps,cuda,auto}` and `--checkpoint-every N` (weights to `<checkpoint>.partial`) are new. Measured on development EMSR578, 8 episodes per update: image model on MPS 13.8 s per update (from ~150 s), no-image ablation 9.8 s on MPS, legacy 9.2 s on CPU. GPU runs are not bit-reproducible across devices. |
| D-55 | Add standard PPO options to the geographic trainer: multiple epochs over whole-episode minibatches, GAE(λ), reward scaling by the running std of discounted returns, batch advantage normalization and approximate-KL early stopping. Defaults reproduce the original update. | The original update took one optimizer step per batch, so 60 updates were 60 gradient steps, and unscaled returns made the critic loss about 5,000 while gradients were clipped to norm 0.5, leaving little policy signal. `--ppo-epochs`, `--minibatches` (groups of whole episodes so LSTM sequences stay intact), `--gae-lambda`, `--reward-scaling` and `--target-kl` enable the standard remedies; scaling statistics include the batch being scaled. Tests: GAE with λ=1 equals Monte Carlo advantages and λ=0 equals one-step TD; the scaler matches the return std; more epochs move weights further; defaults keep the per-episode normalized single-step update. On development EMSR578 (cells ablation, MPS, 4 epochs × 4 minibatches, λ=0.95, scaling, target KL 0.02) the loss is about 0.4 from the first update instead of about 5,000, at about 13 s per update. No performance claim yet. |
